# 管理员用户管理

范围：账户查询与分页、邮箱/角色/状态筛选、创建账户、编辑邮箱和角色、停用与恢复、重置密码。入口位于“我的账户”和“审核工作台”，仅管理员可见。

## 验收清单

- [x] 普通用户、审核员和未登录访问不能读取或修改其他账户。
- [x] 管理员可搜索、筛选、分页；空结果提供清除筛选，接口失败提供重试。
- [x] 创建账户校验邮箱唯一性和角色。创建、登录和重置均要求密码至少 6 个字符，响应和审计不包含密码或哈希。
- [x] 编辑邮箱和角色、停用与恢复会保留原账户和关联数据。
- [x] 不能停用自己或移除自己的管理员权限；始终保留至少一名启用的管理员。
- [x] 并发账户修改在数据库事务中串行处理，并通过版本号阻止旧表单覆盖新修改。
- [x] 角色/邮箱/状态变化或密码重置后，短期与记住登录凭证都失效；恢复账户不会恢复旧会话。
- [x] 重置停用账户的密码不会隐式启用账户；修改自己的凭证后要求重新登录。
- [x] 密码重置、账户创建和属性变更均有审计记录。
- [x] 桌面与手机实页检查列表、长邮箱、表单、确认、空状态和权限状态，无横向溢出。
- [x] 管理员复用已有登录；匿名直访登录后返回管理页，普通角色仍留在账户页。
- [x] 旧数据库迁移保留原账户，并阻止可能恢复已撤销会话的危险回退。

## 数据与权限

`users.session_version` 是账户变更版本。JWT 携带版本，鉴权每次与数据库比较。缺少版本的历史 JWT 视为版本 0，以兼容迁移前的正常登录；账户更新后递增版本并撤销记住登录记录。旧数据保留，页面仅展示管理所需的账户字段。

PostgreSQL 通过事务级 advisory lock 串行化管理写操作；SQLite 通过 `BEGIN IMMEDIATE` 串行化。获得锁后重新校验操作人的当前角色、启用状态和登录版本，防止相互停用的并发请求绕过保护。回退迁移在存在已撤销会话的账户时拒绝执行，防止旧令牌重新有效。

# H07：候选并列时保留可执行任务

## 冻结新题结果

用户已明确授权继续 H04–H08，语义失败后关闭、整改、通过离线与发布验收，再自动继续未测题；传输或解析错误仍停止，总上限八次、不重试、不补题。H04 静态 SQL 审查、H05 受约束翻译、H06 多来源规程核对的四项内容判据通过，原始结果与逐项评审保留。H05 术语表被解析为 existing-tool 假设的非阻断诊断也保留，没有把该假设当成具体平台身份或掩盖为产品事实。

H07 不通过。解释器正确识别仓库编码任务，并保留 CSV、中文、空值、三行合成数据与禁止操作；后端 trial 也保存原题。但多个产品具备相同必要功能、没有足够差异证据指定唯一优先项时，guidance 将主操作改成 compare，executionPrompt=null。普通用户必须先进入候选比较，才能再准备任务，没有在主流程得到复现、最小修改和已有测试的协作步骤。前两项内容判据失败，禁止操作与未伪造执行结果两项通过。已停止后续调用并确认配置关闭，本批已用 7/8、H08 尚未调用。

## 根因与修复

问题在“没有唯一优先产品”覆盖了“已有合格候选且已有可执行计划”。修复保留所有已核验候选、无主选及公开功能依据，不按目录顺序虚构冠军；存在真实 trial 时，主操作使用该计划的完整步骤与可复制任务。用户先确认一个可用入口即可开始，不必逐个对比或测试，差异仍在可选详情中查看。没有计划时仍保留比较/澄清路径，硬条件、费用输入、资格与权限门槛不放宽。

编码步骤按原题先完成复现或静态检查，并说明依据与拟执行操作；只有原题允许才做必要最小修改或运行会改变状态的命令。只读任务仍不写文件、无需生成补丁；代码改动保留补丁、已有测试和实际退出码。原始范围在服务器计划、主步骤、复制、保存重开和报告间沿用，不另写一份前端任务。

未新增 H07 的题干、CSV 字段或样本数匹配规则，不缓存供应商答案。数据、资格与语义解析合同不因候选并列而降级。

## 验收范围与后续

独立合成结果覆盖全部现有协议、中英文和候选顺序置换，核对存在可复制任务且主选始终为空；明确模型 API 与面向普通用户的成品写作路线分别核对，避免混淆。真实应用 API 使用假解释器验证另一项仓库缺陷和普通文本模型任务，检查原始限制、保存、重开与 Markdown。H07 已保存规范化语义的本地重放、实际页面/复制/报告和精确发布，以生成的验收回执为准；它们不是修复后的真实模型重试。

2026-10-22 本地结果：新增检查 30 项通过，相关后端回归 94 项通过，前端 guidance 检查 4 项通过。使用保存的 H07 规范化语义和模拟 HTTP 传输的应用重放通过，确认无任意主选、选产品前可复制完整任务、保存重开及 Markdown 一致，新增供应商调用为零。页面、PDF、CI、精确发布和 H08 继续验收尚须各自回执，不能由这些本地结果推定通过。

发布与离线验收通过后，按用户已确认的连续整改授权仅恢复 H08 一次，仍使用原连接、Astra、4096 输出 token、80 秒、隔离 QA 和合成题干。H01–H03、H07 失败原记录不改为通过；H08 结果不预先判定。当前不能因新题部分通过、修复或 CI 数量而宣布全模块完成，项目 demo/live 门禁也未因此改变。

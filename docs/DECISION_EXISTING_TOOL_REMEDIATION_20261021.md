## 根因与改动

1. 原“已有工具”判断将全文中任意使用提示和任意候选名称相拼接，未核对它们是否属于同一已有工具声明。知识库结论分支还会把自动选出的候选称作“现有平台”。现在共享的 tool_context 只从同一条正向已有/使用声明的对象绑定实体名，排除不可用、资料提及、假设、询问与待选场景；未具名服务保持未绑定。
2. 已有工具不再必须属于公开目录。对于用户所述服务，可直接生成有范围的验收方法，不借用其他产品的功能事实证明它已具备权限、版本或引用能力。语义解释器识别的其他已有工具表达可以作为条件使用，但若没有本地身份来源证明，不绑定目录实体、不标为用户明示的品牌事实。
3. 对已有服务复用当前测试入口，不强制新建平台或知识库。明确要求权限或版本验收时，为每种原题身份准备允许访问、禁止访问、无答案三类问题和人工预期，逐项保存检索、回答、引用、生效版本、越权披露或拒答情况。未提出该范围时，不把整套权限矩阵强塞到普通引用检查。
4. 原 plan 在替换权限/版本步骤时丢掉前面拼入的禁止操作。现在所有方法选择完成后统一追加原始限制，不只保留于题干。最终 recommendation 的对象、理由和边界与 guidance 同步，避免旧目录推荐理由残留为当前服务依据。
5. 前端知识库任务包直接使用服务器的首步准备说明，不再无条件另写“创建知识库、接入 Chatbot”。主动作、复制内容、Markdown、PDF 和离线 HTML 复用同一计划。

没有增加 H03 题干、岗位名、样本数或服务名的任务路由匹配，也没有缓存真实回答作为新用户答案。关系语法是有边界的来源核对，不宣称能独立理解所有自然语言。

## 验证边界

独立最小对照覆盖：明确已有、未知服务、名称只在另一句出现、只有文档、不可用、考虑、假设、询问、名称前缀碰撞，以及主动选择新平台；语义已有工具角色与确定身份分开。另核对无目录候选时仍可生成有边界的服务验收方法。中英文真实应用 API 使用假解释器验证未具名/自定义名称/已知名称、原始限制、三类矩阵、保存重开及 Markdown。

H03 已保存的规范化语义通过本地配置应用工厂和假 HTTP 传输重放，未具名服务不再绑定 Dify，矩阵包含三类问题，原有身份、六份合成制度/两份旧版及禁止外传、禁止助手登录和禁止换平台要求保留。此重放零供应商调用，不是供应商 wire 字节重放，也不是修复后的真实模型复测。H03 原始回执 SHA-256 为 20713182e703313a1913b4b61238357d9f0b2c255b410314da04f7ffe809af12。

本提交完整 CI、前后端精确版本和页面/导出检查以提交后实际回执为准。H04–H08、具体工具证据、普通用户完整验收和项目 demo/live 门禁仍未整体完成，不能用回归数量代替新题语义效果。

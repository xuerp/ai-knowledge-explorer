# 决策助手首次使用流程验收

范围：本地首次使用交互；不代表整个助手、所有渠道资料覆盖或自动模型实测已经完成。

## 已落实的使用路径

1. 先阅读有来源边界的候选建议，选择自己已有入口能使用的一个候选。模型 API 与成品工具明确区分；选择不会开通账户或调用模型。
2. 点击“下一步：准备试用”，定位到任务、输入材料和验收要求。入选依据仍可展开查看，原始来源保留。
3. 在现有产品入口执行任务；也可以先保存未执行的计划。实际结果表单默认收起，执行后再填写。
4. 保存真实结果后使用既有判断更新与同口径比较。展开、收起及保存重开保留草稿内容，不自动将待测变成通过。

有合格候选时，其他候选的资料维护进入“查看筛选依据与其他候选（可选）”。没有合格候选时，实际阻断条件与补资料入口仍在主线，不能以折叠隐藏问题。私人记录的预览和导出进入独立次级操作。

- 类型检查、目标文件 ESLint、格式检查与布局守卫通过。生产构建结果见同目录构建日志。

## 明确未实现的能力

2026-10-15 补记：模型 API 分析新增可选的[本地批量试测与回填](./AUTOMATIC_API_TRIALS.md)，支持自备 API 入口、预先标注的 JSON 样本、费用预览与执行确认。网页不接收密钥或自动执行付费请求。通用账户连接、IDE 实际编辑效果和真实跨产品成绩仍不能由软件流程验收替代；询问该能力不等于授权发送材料或新增付费调用。

不需要先测试所有候选才能阅读基础建议。没有效果证据时只能给出有依据的试用建议，不能制造产品优劣排名。完整模块仍按 `docs/DECISION_PRODUCT_ACCEPTANCE.md` 验收，其他渠道价格、商用条款及数据存储地区覆盖缺项不由本轮 UI 修改补齐。

## 后续变更约束

用户要求已写入 `AGENTS.md` 的 First-use Decision Assistant Contract：新用户应从页面本身理解建议和下一步；选择、外部执行、真实记录分开；普通用户不承担其他候选的知识库维护工作；保留真实记录与草稿。个人记忆增量也已记录该偏好。

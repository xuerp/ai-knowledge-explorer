# 决策助手剩余三项执行与验收

用户要求继续处理自动跨产品实测、渠道证据缺口和依赖告警。本轮沿用完整产品标准，保留已有数据与付费调用的授权范围。

## 固定范围与完成要求

- [x] 依赖：修复真实解析版本，统一安装锁文件，CI 增加实际漏洞审计；前端完整检查、构建通过，推送后复核 GitHub 告警为零。
- [ ] 渠道：从所涉渠道自己的价格、条款及隐私页面留存当前快照、摘录和哈希；将不明费用、积分换算、缓存、实际账单与商用边界分开。待审核事实不直接驱动选型。
- [ ] 自动试测：同批实际样本、预先固定标准和配置、明确入口与版本、有限请求/时间/费用范围、真实失败和用量记录，结果回到既有私人验证流程。没有第二个入口时只允许单入口结论，不能假称跨产品已经实测。
- [ ] 回归：保存既有私人记录；鉴权、候选范围、并发修改、失败恢复和费用未知有独立验证；界面改动完成桌面和手机实看。

资料流：官方页面 → 来源快照 → 具体版本候选及适用边界 → 人工审核 → 现有 Claim/Evidence → 预算/条款筛选。新增事实不自动批准。

实测流：当前分析及合格候选 → 使用者自备实际样本和已标注答案 → 同配置自动请求 → 可追溯结果 → 预览并保存私人记录 → 有范围的判断。外部 API 返回文本不能自行充当评分人，也不执行其生成的任意代码。

首次只读核对：GitHub 14 条开放告警涉及 6 个包，均指向旧 pnpm 锁文件；实际 Bun 也含受影响版本，因此必须同时修复真实构建依赖，不能只移除旧锁文件或忽略告警。

本轮不新增产品订阅、不购买第二个入口、不发送用户仓库或私人文档。新的付费请求仍需明确执行范围，历史调用及原试用记录保持原样。

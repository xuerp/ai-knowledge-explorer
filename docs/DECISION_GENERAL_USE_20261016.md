# 面向通用用户的决策与验证

2026-10-16 用户明确纠正：个人使用的网关不是所有用户的默认渠道，也不是整个助手的完成门槛。共同入口是描述任务、得到带依据的建议、选择实际可用的产品，再按需验证和记录。已有公开依据足以形成有限建议时，不要求用户先补齐其他渠道或拥有第二个账户。

本轮固定范围：通用完成标准、按需渠道约束、验证样本表单、既有运行文件及回填契约、回归与桌面/手机实际操作。模型接口、数据合同和已审核事实不新增；不发起付费请求，不把软件检查当成模型成绩，不改动私人旧记录。

## 验收清单

- [x] 普通任务不继承个人网关、预算或账户；明确指定的渠道仍隔离报价和条款。
- [x] 既有编码、文档问答、抽取等通用场景可继续使用；第二个入口只影响比较，不阻断单产品流程。
- [x] 样本默认逐条填写材料、正确字段和值，保留高级 JSON 入口；空内容不生成伪造样本。
- [x] 保留文本、数字、布尔、空值和嵌套 JSON 的区别；重复字段、无效数字、空输入和超限样本不能导出旧的有效内容。
- [x] 切换填写方式和试用步骤保留草稿；导出的格式与现有本地执行器一致，执行与付费确认边界保持。
- [x] 单候选和多候选的计划、执行回执、预览回填及保存重开保持兼容。
- [x] 桌面与手机实际操作、展开表单及自然换行通过；已有候选长名称沿用六题实际页面验收。

## 本地证据与发布门槛

通用编码、求职抽取和企业文档任务直接使用已审核目录运行后端决策；17 项后端检查通过，包含原六题、严格条件与渠道价格边界。前端样本、既有 API 计划／回执及登录状态 12 项检查通过。实际隔离 QA 页面下载了表单与 JSON 两种运行文件，核对 `001`、`0`、`false`、`null`，并验证无效编辑阻断、步骤切换、私密计划保存重开及同标签页恢复。原始样本未随保存请求上传。

实际页面宽度为 1680 和 390 CSS 像素，页面滚动宽度分别与视口相等，无脚本错误。合成材料只用于软件检查，未产生业务实测或付费调用。证据保存在 `artifacts/decision-task-coverage-20261016/general-samples-verified.json`、`general-form-plan.json`、`general-raw-plan.json`、桌面／手机截图及后端检查日志；这些本地文件不作为公开目录事实。

发布沿用既有 `codex/productionize` → Quality → 预发布精确版本检查 → 正常快进 `main` 流程。以相同 commit 的流水线、前端版本标记与后端 readiness 为发布依据；本地检查不代替部署验证。旧版回滚点为 `e22b03add0d6573aeb392957f6ccd165c76deca4`。

渠道事实只在相关需求下继续补齐。公开功能支持试用资格；真实效果需由实际样本、既定标准与执行记录支持，未测时保持未测。独立新用户研究属于后续产品验证，不能虚构为已完成，也不代替完成当前可实现的功能改进。

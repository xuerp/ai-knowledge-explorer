## 根因与统一修改

根因在方法计划的输入合同：模板把“执行前要准备的材料”写成“用户已经给了的事实”。此前已标注的分类旧题掩盖了这项前提，问题不在 JSON 格式或方法路由。

共享的 decision_workflows.v1.json 是后端方法计划与前端方法识别共同使用的目录。本次不增加题干关键词、供应商条件或任务专用路由，按方法统一修订：

- 分类：先核对已有人工参考标签，没有则由人工建立；歧义留待确认。分类前固定参考，与候选输出隔离，调试与验收分开。未确认参考不评分，缺少某类验收样本标为未覆盖，不能编造召回率或判通过。
- 翻译：有术语表则沿用，没有则标记不确定术语，可先按现有原文开始；不把术语表当成必备既有输入。
- SQL：使用脱敏 SQL 和已提供的表结构，有现成计划才引用实际节点；没有计划也可先静态审查，不要求执行 EXPLAIN、连接数据库或虚构运行数据。已有计划仍可使用，静态推断不代表实测提速。
- 资料对照、表格、录音、图像编辑和截图审查：明确准备获准输入及缺失处理，不声称材料、元数据、参数或入口能力已经齐备，继续保留未知和各自能力边界。

通用文本试用协议与任务包允许原题限定的真实或合成材料。任务包的 Markdown 和离线 HTML 现在共用同一组准备说明，包含建立参考答案的条件与候选输出不能充当自身参考的边界。没有增加模型调用或改变自动测试配置。

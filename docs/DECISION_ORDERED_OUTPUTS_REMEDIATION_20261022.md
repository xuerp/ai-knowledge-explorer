# H08：明确顺序的文本交付物不能被单方法覆盖

## 真实新题结果

H08 从普通 staging 入口实际调用一次，解释、持久化和 Markdown 传输成功，但冻结内容判据仅 1/4 通过，整体失败。解释保留“先分类、再按分类结果生成周报”及原始限制，主方法选择 classification；规划器随后使用单一分类模板，周报与证据编号只剩原题和限制中的文字，没有独立交付步骤和依赖核对。没有把复制到原题当成两个目标均已覆盖。

本批八次已全部使用，累计实际调用 27 次。H01、H02、H03、H07、H08 的真实失败记录保留，H04、H05、H06 首次通过四项内容判据；不同版本逐题整改后的这组结果不是最终版本统一盲测成绩。配置已关闭，不重试、不补题、不续额。

## 修复与范围

新增共享的原文步骤规划：只读取已验证的正向 goal/output 引文，在文本处理范围内保留明确的 first/then、先/再等顺序；原句仍须可回到用户输入。精简解释将首目标与后续 output 分开时，核对其原文段落，但每个步骤仍须覆盖已验证的正向引文。条件、禁止项、缺失材料不能凭顺序词变成目标，不猜无顺序的并行任务，也不另写“周报”或特定样本数规则。

计划显式列出每步交付，使用原题指定的材料；只有原题要求依赖前步时才使用其结果，不把时间顺序强行当成材料依赖。保留编号/来源位置、人工参考与分流、缺失输入恢复、无依据内容未知及全部步骤分别验收。任何一步未执行或缺交付，不能将其他步骤当成整项通过。原有方法检查与硬限制继续保留。

有步骤计划不代表一个产品已支持整条链路，最终建议因此保持有前提、无主选和无全流程合格候选，提供可复制的步骤任务。只读、预算、排除、解析失败和未支持媒体门槛不能被此路径覆盖。仓库复现/修改/测试使用已有专用编码协议，不因多个阶段丢失已审核编码候选。

同一服务器 trial 驱动主操作、复制、保存重开、Markdown/PDF 与既有任务说明，不增加前端另一个事实源。对未明确写出顺序、未被解释器提取的额外交付和任意跨工具任务，仍不宣称已经全面理解或完成工具核验。

## 验收边界

新合成题覆盖评论分组后总结、翻译后术语/日期/待办、资料差异后审阅表、保留文件名与小数的英文三步任务；检查中英文页面用语、逐步交付、正向来源、依赖、排除和未支持任务。另一个质检备注到交接说明的真实本地 API 测试验证保存、重开与 Markdown。

H08 保存语义的假 HTTP 重放、实际页面/复制/下载及发布，各自保留回执，均不得计作修复后的真实模型重试。本轮不能因离线检查或 CI 通过宣布任意新题可靠、模块产品验收完成或项目解除 demo。后续真实模型泛化证据仍缺，当前授权次数为零。

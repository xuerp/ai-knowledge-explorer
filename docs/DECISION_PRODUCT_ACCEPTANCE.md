# 决策助手产品完成标准

本标准覆盖整个决策助手及研究报告。整改需求以[全模块规格](DECISION_MODULE_REASSESSMENT_SPEC_20261016.md)为准，当前验证范围见[项目验证记录](portfolio/VALIDATION.md)。既有测试、候选生成、任务包下载和部署成功都不能单独证明模块完成。

目标：中文产品与技术用户在七个已支持场景中，从自己的任务与使用条件得到可解释的候选和可执行下一步；实际结果保存后形成有范围的判断。未知条件必须得到处理路径，不要求普通用户承担知识库审核工作。不要求拥有第二个产品账户才能使用单产品流程。

| 验收 | 完成要求 |
| -------------- | ---------------------------------------------------------------------------------------------- |
| 任务入口 | 七个任务示例不强塞预算/容量/部署；技术条件按需展开，登录后任务保留 |
| 条件筛选 | 硬条件真实生效；缺项、冲突、排除分别呈现，不以未知推断支持或免费 |
| 回答主线 | 明确对象、功能依据、限制和下一步；顺序不伪装性能排名 |
| 资料维护 | 从结果提交真实缺项，持久化进度、维护队列可处理、重新分析核验；处理请求不能替代事实审核 |
| 首次试用 | 选一个可用候选，拿到任务、材料要求、操作和验收标准，在已有入口执行；未执行不产生数值或通过状态 |
| 私人结果 | 真实入口/版本/样本/标准/日期和结果保存重开；草稿、其他账户、旧修订不驱动建议 |
| 判断更新 | 单产品形成限定判断，多产品仅同口径比较；失败/未测/未知费用不能得到主选 |
| 报告 | 分析与私人记录分开、源依据保留、PDF/Markdown可下载且排版可读 |
| 普通使用与恢复 | 桌面/手机、长名称、展开、稀疏/冲突/失败、重试不重复创建；新用户知道下一步实际操作 |
| 真实资料覆盖 | 对常见明确条件有当前且可追溯的必要依据；缺项不能让主要场景普遍停在未知；渠道条件按实际需求核验 |
| 真实使用效果 | 对已有真实测试保留入口与样本边界；新场景在没有实测时明确为候选/待测，软件 QA 不能冒充产品成绩 |

公开资料必须经过采集、来源快照、实体与边界校验、事实审核后才能驱动选型。价格与许可按对象、版本、日期及渠道分别审核，不继承其他批次的批准。维护请求仅提供公开对象与缺项，研究题目、文件和私人笔记不得进入公共维护队列。

完成判定：核心项均需有当前证据，且没有阻断常见任务的资料或操作缺口。不得缩小分母，将维护请求创建当成资料已补齐，或将任务包下载当成业务实测完成。有限场景通过不扩展为全部市场、渠道和地区已覆盖。

独立首次使用验证采用[五人用户测试脚本](portfolio/user-testing/USER_TEST_SCRIPT.md)，实际参与者记录与软件回归分别判断。外部发布和新付费调用遵循用户实际授权。

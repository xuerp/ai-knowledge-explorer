# 决策助手失败任务整改与验收

本轮修复原始 N1–N8 暴露的需求理解、约束丢失和派生结果不一致。原始探索验收是 0 完整通过、1 部分通过、7 失败，历史结果不改写。本文件不能作为整个模块完成、任意新任务可用或解除 demo 的证明。

## 根因与实现

1. 正向任务、禁止项和缺失材料混在一起参与词匹配。共享子句规则现在区分作用域，支持一句话内正向材料与缺失材料并存；禁止抽取或回复不再成为另一项任务。未知的并行子任务仍保留，不能因无对应场景而丢失。
2. 音频长度被当成执行期限。期限现在要求明确的执行关系；九十分钟录音与十五分钟内完成分别处理。不能上传和公司机器限定进入部署条件，显式云选项冲突不会被静默放宽。
3. 关键词路由不足以处理开放表达。新增服务器任务解释接口，接收精确原文片段、角色、指纹和限定方法；客户端不能替换服务器解释。理解任务与存在已审核产品路线分开。来源有效不等于语义正确，不能把 validated 计数当质量成绩。
4. 解释校验存在误拒绝：已理解但场景为空、版权声明角色、带数量的材料和严格 JSON 外层包装。现在只做可审计、来源保真的归一化；伪造片段、错误指纹、额外产品事实和任意包装仍拒绝。明确约束只能补回，不能弱化。
5. 最终指导与早期试用计划冲突。现在统一协调最终结果：澄清、阻断、未覆盖时移除旧候选与试用许可；有条件的方法不把所有文本模型当成业务合格候选。
6. 页面、复制和报告分别拼接造成漂移。复制任务由服务器从同一计划生成，含原题范围、步骤、指标、合格标准及未执行边界；保存重开和 Markdown 保留同一内容。报告按实际建议对象筛选，不再附带整组无关模型资料。

影响链路：共享目录与数据契约 → 解释与确定性约束 → 场景及证据筛选 → 计划与最终指导协调 → API/持久化 → 页面/复制 → Markdown/PDF。用户真实记录、生产资料模式和既有审核事实不在本轮替换范围。

## 未完成的产品边界

服务器默认解释器未配置，不读取现有 .env 密钥自动启用长期调用。现在有可注入解释接口和有界手动验收适配器，但进程内计数不能作为生产费用上限。开放问法仍需显式接通受控解释服务并独立验证，不能用冻结题回放冒充泛化解决。

之前独立题 U2 价目表不同表述、U3 论坛分流、U4 逐字稿、U7 手册冲突的未识别基线仍保留；没有剩余额度进行新的真实解释验证，也不通过继续增加题目关键词宣布解决。音频、图像和视觉审查尚缺具体产品的完整证据；方法说明不能替代证据。生产发布和 demo 状态不因本轮回归通过而改变。

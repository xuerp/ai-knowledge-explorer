## 根因与修改

1. 来源校验只证明引文在原题中，未证明 deadline 角色有执行时限依据。现在以共享的 execution_bounds/deadline_from_quote 核对引文所在位置；启动请求、素材时长与数据时间范围不能借用其他句子的真实时限。
2. 原消费者直接以模型标记的整句作为 time_limit。现在仅消费经过核对的时长或完成时间值；旧保存回执即使保留 validated 标签，也不能绕过此检查。
3. 无法证明的 deadline 引文保留为 condition，并记录 unverified-deadline-role。明确原始要求没有删除；严格校验入口也会拒绝未经纠正的错误期限角色。
4. 额外 API 回归暴露未收录动词的否定要求会遗漏。限制保留使用宽于路由排除的原文否定检测，不再依赖操作动词目录；保留“不连接”等条件不会把“不合格品的投诉需要分类”整个目标排除。

没有增加题干、产品名或任务词的路由匹配规则，没有缓存真实响应作为用户答案。H01 在失败后进入回归材料，不能再标作未见新题。

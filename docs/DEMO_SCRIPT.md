# AI Radar 演示脚本

目标：证明 AI Radar 不是新闻站、排行榜或普通聊天机器人，而是一套以时间、关系和证据为核心的持续 AI 情报系统。

## 60–90 秒作品集视频

### 0:00–0:10｜产品是什么

画面：打开 <https://ai-radar-staging.1966761779.workers.dev/>，停留在 Hero 和 Trust Layer。

讲解词：

> AI Radar 持续追踪 AI 模型、Agent 与产品生态的官方更新，把分散信息整理成可验证事实、时间线和关系。

### 0:10–0:30｜Timeline

画面：打开 `/knowledge/model/gpt`，展示最近重要变化、版本导航、Timeline 和来源入口。

讲解词：

> 它不是每次重新生成答案，而是长期维护实体状态。每条重要变化都有日期、可信状态和证据。

### 0:30–0:50｜Compare

画面：打开 `/compare`，默认展示 GPT、Claude、Gemini；切换到具体版本。

讲解词：

> Compare 把长期定位和具体版本能力放到一致维度中，不需要用户每次重新设计 Prompt。

### 0:50–1:10｜Research

画面：打开 `/ask`，运行第一条预置问题，展示事实、推断、引用和覆盖边界；再点击 MCP 问题展示证据不足拒答。

讲解词：

> AI Radar 只基于已收录 Claim 和 Evidence 形成结论。证据不足时，它会明确拒答，而不是补齐一个流畅但无法核验的答案。

### 1:10–1:30｜可信闭环

画面：打开 `/admin/review-demo` 或 `/case-study` 的关键决策区。

讲解词：

> LLM 只能生成 Candidate，不能直接定义事实。证据锚点、严格校验、语义去重、冲突检测和风险分级审核通过后，内容才能进入公开知识库。

## 三分钟面试演示

### 0:00–0:25｜首页：5 秒理解产品

1. 指出主标题“持续追踪 AI 世界正在发生什么”。
2. 展示 Claim、Evidence、Relation、Timeline 四项 Trust Layer。
3. 指出 `demo/cached` 标签与内置快照提示。
4. 下滑到“为什么不直接问 ChatGPT”和三个核心体验。

讲解词：

> ChatGPT 适合一次性研究，AI Radar 解决长期追踪、反复核验和跨时间比较。Showcase 可以使用明确标记的精选快照，但不会冒充实时正式数据。

### 0:25–0:55｜GPT 档案：实体与时间

1. 点击 GPT 进入 `/knowledge/model/gpt`。
2. 展示知识导读、关键事实、最近变化、关系、Timeline 和 Evidence。
3. 切换系列与具体版本。
4. 依次切换“通俗 / 产品 / 技术”：产品模式把使用场景、限制和版本选择提前，技术模式把结构化档案、关系、时间线和证据提前，并默认折叠使用场景。

讲解词：

> 当前三种阅读偏好已经可以保存，但正文编排差异仍待完成，因此本次演示不把它声明为正式能力。完成后，三种模式仍将共用同一份底层知识，只改变呈现重点。

### 0:55–1:25｜Compare：一致维度下的路线差异

1. 打开 `/compare`。
2. 指出默认 GPT、Claude、Gemini 系列级对比。
3. 切换到具体版本，查看上下文、价格、模态、工具与可用范围。
4. 说明演示价格与未来版本不作为采购结论。

讲解词：

> 默认对象只是体验入口，底层仍接受任意可比较模型。数据不足时不会要求模型编造缺失维度。

### 1:25–1:55｜Research：逐结论引用和可信拒答

1. 未登录打开 `/ask`。
2. 运行 GPT 与 Claude 代码任务问题。
3. 展示已核验事实、基于证据的推断和来源列表。
4. 运行 MCP 集成问题，展示 `insufficient-evidence`。
5. 说明登录后才创建私密真实研究记录。

讲解词：

> 公开预置问题不需要登录；真实用户研究会保存到私密账户。两者都遵守相同的 Evidence 契约。

### 1:55–2:25｜关系图谱：回答具体问题

1. 打开 `/graph`，选择 GPT 生态组成。
2. 展示一跳、二跳与最短路径。
3. 选择一条关系边，打开来源证据。

讲解词：

> 图谱不是装饰动画。它用于回答“谁和谁有关、是什么关系、依据是什么、关系路径如何解释”。

### 2:25–3:00｜Case Study 与审核闭环

1. 打开 `/case-study`，快速展示 Problem、Product Pivot、Key Decisions 和 Showcase/Live 边界。
2. 打开 `/admin/review-demo`，展示采集 → Diff → 抽取 → 候选 → 审核 → 发布。
3. 指出真实 `/admin/review` 仍受 JWT/RBAC 保护。

收尾词：

> 这个项目最关键的产品设计不是模型本身，而是没有让模型拥有直接定义事实的权限。AI Radar 尝试解决的是：怎样把概率性的 LLM 输出，转化成可以长期依赖的知识产品。

## 演示前检查

```bash
bun install --frozen-lockfile
bun run check
```

- 使用 1440px 桌面窗口准备主演示。
- 额外准备移动视口，确认首屏、CTA 与底部导航没有横向滚动或遮挡。
- 保持中文界面，按需要切换一次 English。
- 不把演示版本、指标、价格或日期表述为当前采购事实。
- 不在演示中触发外部模型调用，避免产生额外费用和不可控等待。
- SMTP 尚未接通，不演示真实邮件投递。
- 公开数据仍为 `demo/cached`，不表述为正式实时数据。

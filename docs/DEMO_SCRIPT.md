# AI Radar 三分钟演示脚本

目标：在三分钟内证明 AI Radar 不是新闻站、排行榜或普通聊天机器人，而是一套以时间、关系和证据为核心的 AI 技术生态知识系统。

## 0:00–0:25｜首页：变化，而不是新闻流

1. 打开 `/`。
2. 指出首屏同时包含“与你相关的最新变化”和“全行业不可错过”。
3. 展示 “Demo data” 与数据新鲜度标记。
4. 说明：个性化不会隐藏全行业重大事件。

讲解词：

> AI Radar 维护固定实体的长期知识。每次变化都会回写到实体、时间线和关系图，而不是阅后即焚的新闻卡片。

## 0:25–0:55｜GPT 档案：六段式知识结构

1. 点击 GPT 变化进入 `/knowledge/model/gpt`。
2. 展示结构化档案、最近变化带和可信度。
3. 向下展示局部关系图、故事化时间线、对比入口、问答入口和原始资料。
4. 切换一次“通俗 / 产品 / 技术”阅读模式。

讲解词：

> 三种阅读模式共用同一份底层知识，只改变解释深度，不维护三套互相冲突的事实。

## 0:55–1:30｜大图谱：回答具体关系问题

1. 打开 `/graph`。
2. 搜索并定位 “GPT 系列”。
3. 选择一条边，打开来源证据检查器。
4. 在起点与终点中选择两个实体，展示最短路径高亮。
5. 调整关系可信度或时间筛选；在手机演示时打开筛选抽屉和列表视图。

讲解词：

> 图谱不是装饰动画。节点、边、邻域、时间和路径必须帮助用户回答“它和谁有关、关系依据是什么、在什么时间有效”。

## 1:30–2:05｜AI 研究：逐结论引用

1. 打开 `/ask`，使用预设的 GPT 与 Claude 代码任务问题。
2. 指出事实、推断、未核验和冲突被分开呈现。
3. 点击“打开完整研究记录”。
4. 在 `/research/research-demo-gpt-claude` 展示逐结论引用、研究步骤和可信边界。
5. 演示 Markdown 下载或“打印 / PDF”，再打开公开分享页。

讲解词：

> AI 回答不能用流畅文本掩盖证据缺口。每个关键结论要么绑定来源，要么明确说证据不足。

## 2:05–2:30｜个性化：用户可控

1. 打开 `/onboarding`。
2. 选择一个实体和一个方向标签，填写一句自然语言兴趣。
3. 展示行为学习开关并保存。
4. 在 `/following` 展示推荐理由、提醒强度、删除兴趣、暂停学习和清空画像。

讲解词：

> 个性化可查看、可修改、可暂停、可清空。演示版只保存在当前设备，不上传行为数据。

## 2:30–3:00｜审核后台：可信不是一句口号

1. 从首页待审核卡片或直接打开 `/admin/review-demo`。
2. 展示采集 → Diff → 抽取与消歧 → 冲突检测 → 人工审核 → 发布流水线。
3. 打开候选 Claim，展示社区来源、双时间字段和“需要更多证据”。
4. 切换信源与同步运行视图。
5. 指出后台严格只读，没有批准、删除或发布按钮。

收尾词：

> 自动采集和 AI 抽取只生成候选，不能直接成为事实。AI Radar 的核心竞争力是可追溯、可审核、保留历史状态的知识闭环。

```bash
npm run test

```

- 额外准备 390px 手机视口展示图谱和研究页。
- 保持中文界面，按需要切换一次 English。
- 不把演示版本、指标或日期表述为当前真实事实。
- 不演示不存在的登录、抓取、审核写入或在线模型调用。

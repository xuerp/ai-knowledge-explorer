# Spec 覆盖与交付边界

## 演示流程，尚未连接真实服务

- AI 研究答案来自强类型演示快照，不会调用在线模型。
- 审核后台为只读演示，不允许批准、拒绝、删除、抓取或发布。
- 通知和每日摘要只验证前端状态；尚未发送真实站内事件或邮件。
- 公开研究页读取演示记录；尚未执行真实发布权限与持久化。
- `KnowledgeRepository` 已保留真实 API 边界，但当前未配置 `VITE_API_BASE_URL` 时使用演示 adapter。

## 后端阶段必须完成

以下项目不能仅靠 Lovable 页面或本仓库前端伪造：

1. FastAPI、PostgreSQL、迁移与受保护写接口。
2. 每 2–4 小时采集、快照 Diff、去重、实体消歧、结构化抽取与冲突检测。
3. 人工审核写操作、审计日志、发布记录、限流和权限。
4. 托管认证、私密研究归属、跨设备同步和真实公开分享 URL。
5. LLM 供应商适配、图谱查询、外部临时检索和引用校验。
6. 站内通知事件生成与事务邮件投递。
7. Spec 的正式数据验收数量、来源覆盖率和黄金研究问题评测。
8. 公开 HTTPS 部署、真实 API 配置、监控与恢复策略。

## 当前推荐交付顺序

1. 先以当前分支作为可演示、可继续开发的前端基线。
2. 下一阶段优先实现 API 契约、数据库 Schema 和认证，不再消耗 Lovable credit 做结构性修改。
3. 接入第一条“来源 → 候选 Claim → 人工审核 → 正式发布”的纵向闭环。
4. 最后接入研究模型、通知邮件和公开部署，再执行正式数据验收。

## 演示与真实能力的区分

- `/admin/review-demo` 是明确标记的只读演示；未登录的 `/following` 保留演示引导，`/ask` 可运行三条明确标记的预置研究路径。
- 已登录且配置 API 时，`/account`、`/following`、`/ask`、私密研究详情和 `/admin/review` 均连接真实后端。
- `AI_RADAR_DATA_MODE=demo` 时公共 API 仍明确返回 demo/cached。
- 抽取、邮件和云部署只有在配置真实外部服务后才会执行。

## 阅读模式当前边界

“通俗 / 产品 / 技术”目前已经具备偏好保存和设置入口，但主体内容尚未形成可验收的编排差异，因此不能继续作为完整能力对外声明。真实阅读模式、事实合并、事实替代和历史分页以后续的[阅读模式与知识生命周期治理 Spec](READING_MODE_AND_KNOWLEDGE_LIFECYCLE_SPEC.md)为准。

## 当前正式数据差距

Spec 要求正式图谱约 40–50 个有效实体、150 条已审核 Claim、核心对象至少 5 条关系，并且 20 个黄金问题至少 85% 通过。

当前在线演示目录为 49 个实体、71 条带来源关系、40 条证据、55 条时间线事件和 23 条带来源 Claim。目录包含模型系列、具体版本、Agent、框架、论文和 Benchmark 等节点。它用于验证产品和工程闭环，不属于正式数据验收。`GET /api/v2/admin/data-quality` 会机器化报告尚未达到 150 条人工审核 Claim，以及 17 个核心实体约 49 条关系覆盖缺口，避免人为误报。

`GET /api/v2/admin/golden-questions` 会实际执行 20 个黄金问题的证据可回答性评估，检查实体解析、一跳关系、带来源时间证据、官方来源与最短路径等确定性约束；结果同时并入数据质量报告。它用于阻止“只有问题清单、没有通过率计算”的形式验收，不生成或伪造自然语言答案。

完成正式验收仍需：

1. 继续核验并扩充真实官方信源。
2. 使用已接通的结构化抽取供应商生成候选，而不是直接生成事实。
3. 人工逐条核验 Claim、关系、有效期和引用。
4. 扩充到数据门槛并运行 20 个黄金问题。
5. 由产品或研究负责人签署数据验收。

## 外部交付边界

在线预发布环境和抽取供应商已经接通；以下仍需要用户的外部账号、资源或决策：

- 自定义域名及其 DNS、证书验收。
- SMTP/事务邮件供应商与已验证发件域。
- 外部监控、告警接收人与备份恢复演练。
- Cron 已在预算确认后调整为每 30 分钟一次，后续需观察供应商额度与失败率。

因此，当前可以声称系统已公开预发布并通过工程质量门禁，但不能声称自定义域、邮件送达、外部灾备或正式数据研究已经完成。

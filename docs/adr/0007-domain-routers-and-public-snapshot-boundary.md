# 0007：领域路由与公共离线快照边界

状态：采用。适用范围为应用结构和数据加载，不代表全量数据或产品效果已验收。

## 背景

HTTP 端点与共享业务辅助函数集中在 `main.py` 的应用工厂中。前端页面静态导入离线适配器，适配器再直接读取后端目录，导致 API 部署也携带完整离线数据及历史种子。

## 决定

- `main.py` 负责应用组装、生命周期、中间件及路由注册；`api/` 按领域定义路由。
- `api/dependencies.py` 复用原有会话和鉴权规则，从当前 `request.app.state` 获取每个应用实例独立的服务，避免模块级可变服务实例。
- 目录、抽取、审核、报告和诊断的共享逻辑放入 `services/`，由 `runtime.py` 组装。事务提交和回滚仍由原业务路径控制；会话依赖只负责释放会话。
- 前端通过脚本生成公共离线快照，保留完整公共目录并清空账户活动。生成物不可手工编辑，检查与 CI 阻止上游和生成物漂移。
- API 构建移除离线加载分支；无 API 配置的离线构建按需加载生成快照。请求失败显式呈现错误，不注入示例事实。
- 历史种子按领域拆分，保留原导出入口与内容；其用途是复现和测试，不作为正式模式的客户端数据来源。

## 验证与取舍

结构调整保留 HTTP 路径、参数、安全定义和响应格式，使用拆分前后的完整 OpenAPI 对照及既有回归检查实际行为。页面改动另检查桌面、手机、筛选、登录恢复和退出。

生成快照只是明确数据边界，静态导入完整生成物不会自动减包。包体收益来自 API 构建删除离线分支，以及离线构建的异步加载；必须分别记录实际产物，不能把原始 JSON 大小当作浏览器传输量。

Provider 扩展保持现有范围，不因结构整理新增供应商、付费调用或大模型生成能力。历史回执保留原有日期和范围，新的原始运行产物放入忽略的 `artifacts/` 或 CI artifacts。

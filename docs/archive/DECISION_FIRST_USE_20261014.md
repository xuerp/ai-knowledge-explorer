# 决策助手首次使用流程与界面验收

2026-10-15 更新：按截图逐项改造分析结果、任务准备、实际记录与下载说明。范围是交互与软件验收，不代表全部渠道资料或真实跨产品成绩已经补齐。

## 当前使用路径

1. 先看候选建议、任务相关理由和适用范围。筛选计数直接展示；说明在独立提示区，不与结论正文争夺层级。
2. 选择已有入口能使用的候选，点击“查看试用任务”。只有一个合格候选时预选该项，仍需点击才能准备；这不证明账户可用，也不会调用产品。
3. 在“试用与我的记录”中直接点击“复制试用任务”，粘贴到所选产品，并附上真实材料。编码新手默认先试一个报错或小功能，不要求第一次就完成三题对比。
4. 下载不是必需步骤。“下载任务说明”提供自带样式的独立 HTML，可离线阅读或打印；Markdown 保留为编辑器格式。完整对比方案与验收标准是可选补充。
5. 用过以后切换到“记录实际结果”，填写并保存。准备、记录之间切换保留草稿，保存重开保留原记录；未执行项目不会自动通过。

模型 API 与成品产品继续区分。模型 API 的批量运行是独立的可选能力，使用说明见 [本地批量试测](../AUTOMATIC_API_TRIALS.md)。网页不接收密钥、不自动执行付费请求。

## 截图问题对应处理

| 问题                 | 当前处理                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------- |
| 说明与正文混杂       | 结论、下一步、计数和范围说明分别呈现，辅助说明使用独立低强调提示区                           |
| 一行统计还要展开     | 直接展示计数，不再独立折叠                                                                   |
| 主流程多层箭头       | 试用区不再外层折叠，准备与记录用明确按钮切换                                                 |
| 父标题小于子标题     | 结论 24px（手机 21px）、主区 20px、子区 17px、正文与说明逐级区分                             |
| 内容局促、操作不明显 | 使用可用容器宽度；主操作为按钮、修改与更新为文字操作，资料入口为链接式展开、比较项为整行标题 |
| 不理解任务包         | 默认展示具体可复制提示，下载降为可选；说明文件不执行任务，不包含成绩                         |
| 下载内容默认大标题   | 增加自带字体、标题、行距及打印样式的离线 HTML；原 Markdown 继续保留                          |
| 重复功能或空提示条   | 相同功能描述去重，无复核内容时不显示空提示背景                                               |

有合格候选时，其他对象的维护进入“筛选依据与其他候选”。没有合格候选时保留实际阻碍与恢复入口，不能用折叠掩盖问题。私人记录的完整配置及导出仍为次要操作。

## 当前软件验证

隔离本地 API、专用 QA 账户和独立数据库使用当前公开已审核资料生成编码、API 与严格条件三个分析，没有写入原用户记录或调用供应商。

- 实际复制内容与任务提示一致（按 Windows 标准换行归一化核对）。
- 实际下载排版版 HTML 与 Markdown，并检查离线文档、手机和打印样式。
- 准备／记录切换保留已填内容；保存并重开成功，所有 QA 检查继续待验证，没有生成产品成绩。
- `/ask` 恢复结果及完整研究报告的共享决策区均检查；桌面 1440、宽屏 1920、手机 375，另含英文深色、展开辅助内容与条件不足状态。
- 13 张实际截图、正常段落可用宽度及页面溢出测量保留在 `artifacts/decision-ui-rebuild-20261015/`。正常块文本与父容器可用宽度相差不超过 2px，页面横向溢出不超过 1px。
- 新增离线说明的用户内容转义、无远程资源及编码单任务起步检查；其余门禁与构建以相应 GitHub Quality 记录为准。

## 历史证据与持续约束

2026-10-14 的首次流程验收为 55 项相关前端回归和 8 项浏览器流程检查，证据仍在 `artifacts/decision-first-use-20261014/`；它们不是本轮新增结果。

不要求测试所有候选才能获得基础建议。没有效果证据时只提供有依据的试用建议，不能制造产品排名。完整助手仍按 `docs/DECISION_PRODUCT_ACCEPTANCE.md` 验收；本轮 UI 不会补造渠道价格、许可或数据存储地区事实。

首次使用和文字宽度约束继续写入 `AGENTS.md`。主流程及记录内容必须在改动后通过实际桌面／手机检查；截图与软件 QA 不能冒充模型业务实测。

## 2026-10-15 展开区域修正

移除将所有 summary 画成边框按钮的全局规则。比较维度采用紧凑的整行标题，候选的功能、缺项和引用合并为一个资料入口；修改要求与重新分析直接在同一行显示。关闭时不保留展开内容的上下间距，报告原始来源与结果区之间也缩短间隔。

未入选候选的状态来自本次分析返回的 gap 原因：知识库未收录、资料未结构化、依据需重新核验、事实冲突或用户需要补充条件分别表达。它们都不能证明网上没有资料或产品不支持。实际效果仍需真实任务验证，界面改动不会提升候选资格或补造证据。

参考 [GOV.UK 的补充详情](https://design-system.service.gov.uk/components/details/)和 [Carbon 的折叠行](https://www.carbondesignsystem.com/building-blocks/core/components/accordion/guidelines)，区分低强调辅助内容与成组资料导航，不把所有信息转换为同一种按钮。

本轮独立验收证据位于本地 `artifacts/decision-layout-clarity-20261015/`，覆盖实际规则生成的编码、云 API 和严格条件分析，以及展开的候选、比较维度、手机、英文深色、复制、下载、草稿切换、保存重开。软件 QA 结果不计为模型业务成绩。

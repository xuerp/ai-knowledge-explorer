# 自然问法与首次使用收尾

本轮验收固定为：现有七个用户入口所覆盖的八条场景路线各两题，加五项含糊、否定、硬条件及费用边界，共 21 个新问法。题库在修改识别逻辑前冻结于 `backend/data/decision_first_use_cases.v1.json`。这些是工程编写的任务，不冒充独立受访者，不代表业务准确率或模型实测。现有六题和明确条件必须继续通过。

影响链路：共享场景词表／识别规则 → 前端输入解释及条件确认 → 后端用途识别及候选发现 → 已审核事实筛选 → 建议与试用说明 → 私人结果保存重开。只修改任务理解和首次路径问题，不新增未经审核的产品事实、模型调用、付费入口或数据库合同。

## 固定验收要求

- [x] 原始自然问法从默认空条件开始；没有示例问题暗中附带的任务类型、预算或模态。
- [x] 前后端识别一致，明确区分整套产品、底层模型和开发框架；否定的用途不能抢先匹配。
- [x] 常用问法给出有当前引用的候选；纯文本抽取不额外要求文档／图片输入能力，照片要求保留图像输入约束。
- [x] 含糊问题先澄清；完全离线等硬条件保留；未知工作量和渠道不产生费用赢家。
- [x] 原六题、既有明确指定条件、候选范围、证据和费用边界回归通过。
- [x] 初次访问可从界面完成描述、确认、登录恢复、理解建议、选一个产品、复制任务、切换记录、保存重开及导出；不要求先打开资料审核或本地 API 执行器。
- [x] 桌面和手机、完整展开、长名称及自然换行实际检查，保存截图和交互证据。

发布门槛继续要求完整 GitHub Quality 与现有预发布精确版本核对；只同步此次公开代码、题库及文档，保留无关工作。发布是否完成以相同 commit 的 CI、前后端版本与本地验收回执为准。

## 发现与修复

修改前 21 题只有 3 题符合预期，18 题暴露用途漏认、产品／模型路线混淆或否定用途误匹配。此数字属于这组预先编写的请求，不作为真实用户成功率。前后结果分别保留在 `before-inputs.json` / `before-results.json` 与 `final-inputs.json` / `final-results.json`。

前后端现在读取同一份用途规则：动作意图优先于偶然提到的话题，明确选择的产品类型保持优先，否定分句不参与用途匹配。支持常见转述，同时继续保留条件确认界面。这是有限的规则识别，不宣称无限制的自然语言理解。

“改文件、跑测试、人点确认、中断后续跑”等要求单独进入功能核验。新增的请求表达只用于理解需求，不扩大供应商事实的匹配词表，不凭用户写出的要求制造支持证据。实际来源、Claim 审核、报价和日期门槛保持原样。已有来源满足必要条件时直接形成有限建议；没有新增产品事实或模型调用。

最终 21/21 符合预期，包含含糊题澄清、严格条件阻断及未知费用不产生价格赢家。相关后端 114 项检查通过；新增前端自然问法和原工作流 36 项检查通过。新增前后端回归会随完整 Quality 自动执行。最初新增测试遗漏 V2 合同版本及英文后置否定的失败记录保留，未宣称一次全绿。

实际隔离 QA 通过 HTTP 创建并重开全部 21 题；另从未登录的首次访问开始，通过页面登录后恢复自然问题，完成候选、任务复制、说明下载、记录切换、私密保存重开及 PDF 下载。只写工程检查备注，全部项目保持 pending，没有虚构产品实测。十类正常、含糊和严格条件结果共 20 个桌面／手机视图无页面错误或横向溢出；结论正文宽度等于父容器可用宽度。证据见 `http-verified.json`、`first-visit-verified.json` 及实际截图。

最终补验完整展开的 Agent 功能比较和候选证据区，桌面／手机均无横向溢出或脚本错误，见 `expanded-verified.json`。另加入话题与动作区分、中英文混排、后置否定及原生检索要求的正反向检查；不得因为需求同义表达而扩大事实认定范围。

不把 21 题通过换算为整个人群的可用性结论。独立新用户研究尚未开展；本轮可完成的是自然问法回归和按初访状态进行的实际操作验收，不伪造访谈、用户人数或完成率。明确不支持的网页直接付费调用及自动操作 IDE 不加入这轮范围。

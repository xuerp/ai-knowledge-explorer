# 用户管理模块设计记录

## Overview

范围仅为既有管理面的用户管理扩展（`/admin/users`），以当前实现和 2026-11-10 的隔离 QA 截图为依据。本记录用于维护该模块，不定义全站视觉系统，也不要求新增全站 `DESIGN.md`。沿用 AppShell、共享导航、字体、颜色、表单和弹窗；采用 Operate 模式，让管理员先查找账户，再执行明确操作。

管理员从“我的账户”或“审核工作台”的“用户管理”入口进入。审核员与普通用户没有此入口，直接访问会回到 `/account`。未登录或会话失效时复用账户页登录，并保留 `/admin/users` 返回目标；成功登录的管理员返回管理页，其他角色留在账户页。路由标记为 `noindex,nofollow`，权限仍由服务端校验。

## Layout

- 页面沿用共享外壳，内容居中，最大宽度 `80rem`；水平留白从 `1rem` 增至中等屏幕的 `1.5rem`。标题、简短说明和创建入口在先，搜索筛选和实际账户列表随后。
- 桌面在 `lg` 断点使用邮箱、角色、状态、创建日期、操作五列。邮箱列为 `minmax(0,1fr)`，其余列依次为 `7rem / 6rem / 7rem / 16rem`；行以分隔线组织，便于纵向比较。
- 小屏隐藏列表列头，每个账户自然堆叠为邮箱、角色、状态、日期、操作。标题操作、筛选和行内按钮允许换行，继续使用同一套内容与控件。
- 长邮箱完整显示：网格及内容容器允许收缩，文本使用 `overflow-wrap:anywhere`。对话框同样使用 `minmax(0,1fr)`，宽度为视口减 `2rem`、大屏上限 `32rem`，高度上限 `90dvh` 并允许纵向滚动，防止长邮箱撑出横向滚动。

## Components

### 共享视觉与操作层级

复用共享 Button、Input、Select、Dialog，不建立模块专用 token。创建与常规确认使用现有主色；停用确认使用破坏性按钮；审核入口、搜索、分页、取消使用描边按钮；刷新与逐行编辑、密码、停用/恢复使用轻量按钮。状态同时以“已启用 / 已停用”文字表达，当前账户另有文字标记。保留共享焦点环、禁用反馈和中英文文案。

### 搜索、筛选与分页

邮箱搜索支持完整邮箱或关键词，提交时去除首尾空白并回到第一页。角色提供全部、普通用户、审核员、管理员；状态提供全部、已启用、已停用。切换任一筛选立即回到第一页，刷新保留当前查询条件。

筛选条的字段容器使用 `flex-col gap-2`，避免 Radix 附带的隐藏原生 `select` 影响子项间距。输入、下拉和按钮沿用共享的 `h-9`（36px），同一行的上下边缘对齐；字段之间为 `gap-3`（12px）。手机端两个下拉等分可用宽度，`sm` 起保持原有 `9rem` 宽；搜索与刷新作为一组换行。2026-11-10 已以 320、390、768、1280、1920px 实页和几何测量复核该局部布局。

列表显示服务端总数，以每页 20 个账户分页，并显示当前范围。上一页、下一页在边界或加载中禁用；账户变更导致当前页超出末页时回到有效末页。加载使用状态文字与占位行；无匹配结果给出更换关键词和“清除筛选”路径；连接或列表错误显示提示与重试。

### 创建、编辑与权限

创建对话框包含邮箱、角色、新密码和确认密码，默认普通用户。编辑仅包含邮箱与角色，并按所选角色说明能力：普通用户浏览并保存个人研究；审核员审核资料；管理员管理用户、信源与审核操作。

当前管理员的角色选择与停用按钮禁用；服务端同时禁止自停用、自降权，并要求至少保留一名启用的管理员。停用保留研究与关注记录，界面不提供删除账户操作。

### 密码、状态确认与恢复

创建账户的密码长度为 6–256 个字符，重置已有账户的密码长度为 12–256 个字符。两个表单均要求重复输入，支持粘贴与浏览器生成密码。不一致时在对话框内提示。重置密码和编辑资料说明账户需要重新登录。停用/恢复先展示带目标邮箱的确认说明，停用明确告知访问将被关闭、已有内容保留。

提交期间禁用字段、取消与确认按钮，并显示“正在保存…”，防止重复提交。普通保存失败保留对话框与输入，错误以 `role="alert"` 显示，并提供“刷新账户列表”以关闭旧表单、重新获取账户版本；并发变更等错误可通过此路径恢复。成功后关闭对话框、显示状态提示并刷新列表；关闭时将焦点还给原操作控件。

资料、角色、状态变更及密码重置由服务端撤销目标账户旧会话。修改自己的邮箱或密码后清理本地会话，回到登录页并保留管理页返回目标。会话失效时清空管理列表与打开的操作，进入相同的重新登录流程。

## Do's and Don'ts

- **Do** 保持“查找账户 → 选择操作 → 确认 → 刷新结果”的顺序，并在失败时提供原位修正或刷新恢复。
- **Do** 用完整邮箱识别目标，保留自然换行、手机堆叠、明确标签和键盘焦点反馈。
- **Do** 同时保留入口隐藏、路由检查和服务端角色校验；界面禁用不能代替权限约束。
- **Don't** 将登录页当作用户管理功能，或为此模块建立另一套登录、视觉主题和全站规则。
- **Don't** 用截断邮箱、缩小字体、固定宽表格或横向滚动掩盖窄屏溢出。
- **Don't** 跳过密码或状态确认、关闭失败表单丢失修正机会，或把停用解释成删除数据。

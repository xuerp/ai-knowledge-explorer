# AI Radar：把技术资料变成可追溯的研究依据

## 问题与设计

选择 AI 工具时，产品介绍、技术文档与实际使用结果容易混在一起。信息随版本变化，一个链接也不足以说明哪条事实支持哪项判断。

AI Radar 将资料整理成可以持续检查的知识层，并让研究界面保留证据和限制。这是产品设计假设，不是已通过大规模用户调研证明的结论。

产品流程：选择研究对象 → 查看事实与原始资料 → 带着需求研究 → 检查限制 → 保存研究。资料维护通过候选和审核进入公共知识层。

## 数据模型

| 对象      | 职责                         |
| --------- | ---------------------------- |
| Entity    | 研究对象                     |
| Claim     | 可核对的原子事实             |
| Evidence  | 来源、摘录和观察时间         |
| Candidate | 待审核内容                   |
| Research  | 用户研究记录，与公共事实分离 |

同一 README 的多个摘录不是多个独立信源；采集时间不是产品发布日期；保存研究也不生成产品性能证据。

## 工程取舍

React / TanStack 承载跨页面交互，FastAPI 负责校验和业务边界，SQLAlchemy 与迁移支持数据演进。检索与生成分离，使本地核验可以关闭外部模型服务，仍检查资料引用与实体映射。

专用作品集启动器同时固定浏览器和 SSR 的 API 地址，切换初始资料，避免历史样例与真实 API 混用。后端按资料哈希区分 SQLite 文件，避免重启时继续读取旧种子。

## 结果与边界

本次语料包含 Dify、LangChain 两个对象的六条官方文档事实。它适合解释资料如何进入产品，不足以证明全市场选型质量。

没有用户或商业测量时，不使用增长率、成本下降作为成果。没有新一轮真实模型评估时，不沿用历史准确率。执行证据以 [VALIDATION.md](VALIDATION.md) 为准；作品集范围收窄不意味着历史全产品审计通过。

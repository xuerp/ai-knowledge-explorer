# 简历与面试材料

按实际参与范围调整以下表述，不默认声称全部工作由单人完成。使用 AI 辅助开发时，应如实解释本人负责的需求、判断、实现与验证。

## 简历项目

**AI Radar｜基于证据的 AI 技术研究平台**

React、TypeScript、TanStack、FastAPI、SQLAlchemy、SQLite / PostgreSQL。

- 设计 Entity–Claim–Evidence 知识模型，将研究对象、事实与来源分离，支持在知识库中追溯能力描述的原始资料。
- 实现知识浏览、研究 API 与候选审核等模块，围绕证据不足、资料时点和公共事实发布设计边界。
- 建立固定版本官方资料的复现入口，提供来源摘录与 SHA-256 校验，隔离本地数据库和外部服务配置。

不添加未经验证的用户量、准确率、收益或“生产级全自动闭环”。当前资料规模小，不宜作为海量数据经验。

## 90 秒介绍

AI Radar 关注 AI 工具选型时的证据问题。我把对象、事实、来源和研究结果分开建模，让判断可以追到原始资料。前端使用 React 和 TanStack，后端使用 FastAPI 与 SQLAlchemy。项目包含知识浏览、研究与审核模块；作品集复现版本使用固定版本的 Dify 和 LangChain 官方资料，并提供可重跑的来源校验。工程重点是资料与推断的边界、前后端数据一致性和运行隔离。当前没有用文档描述代替模型实测，也没有把预发布状态说成生产完成。

## 面试追问

**为什么不直接做聊天界面？** 聊天是交互方式。这个项目需要保留可复用的事实、来源、审核状态和研究记录，因此先建设知识层。

**如何减少无依据结论？** 候选与已审核事实分离，事实引用具体来源，缺少成本或性能证据时保留未知。这降低风险，但不宣称彻底消除幻觉。

**为什么只展示两个对象？** 当前资料可以逐条复核。历史更大语料与评测没有重新核对，不能当作当前成绩。

**下一步是什么？** 完成真实资料上的浏览器流程与保存导出验收，再扩展代表性来源与问题集；自动采集与模型评估分别设置质量、费用与授权边界。

# 运行与演示路线

先按[根目录 README](../../README.md)启动真实来源前后端。安装依赖需要网络，本地运行不需要模型密钥。

## 5 分钟讲解顺序

1. 打开 `/knowledge?category=all`，说明资料范围为 Dify、LangChain。
2. 进入 Dify 详情，查看知识要点和来源，在固定 commit 的官方 README 核对原文。
3. 展示 `sources.json` 的版本和哈希，运行 `python scripts/verify-portfolio-sources.py --fetch`。
4. 进入 `/ask`，输入“Dify 的官方资料说明了哪些 RAG 和工作流能力？”进行现场检查。结果必须受资料约束；失败时说明缺口，不替换成预写答案。
5. 输入“Dify 和 LangChain 哪个实际部署成本更低？”检查资料边界。当前没有成本实测，不能给出真实成本排名。

第 4、5 步是检查任务，不是已通过的用户研究或模型测评。保存、重开、导出和移动端也必须实际执行后才能标记通过。当前状态见[验证记录](VALIDATION.md)。

## 运行说明

- 前端 `127.0.0.1:8085`，后端 `127.0.0.1:8004`。
- `scripts/dev-portfolio.mjs` 为浏览器、SSR 和初始快照选择相同资料。
- 后端使用专用数据库，不读取历史研究答案作为演示结果。
- 资料更新后使用新数据库，旧文件留在本机，不自动删除。
- 来源无法访问或哈希不一致时校验失败，不能改记为通过。
- 端口占用时正常关闭此前启动的本项目进程，不要删除数据库解决端口问题。

官方文档证明作者如何描述功能，不证明工具在你的任务中效果最好。演示输入不能包装为客户案例。

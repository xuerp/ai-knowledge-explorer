# AI Radar 五人用户测试脚本

## 目的与边界

本测试对应 [产品路线图](../../../PRODUCT_ROADMAP.md) 第 8 节“验证指标”和 Phase 5 第一项，用 5 位目标用户的真实任务发现理解和操作障碍。

- 测的是产品，不是参与者。结论只写观察到的事实，不推算全体用户比例。
- 指标用于发现问题和比较迭代，不设达标线，也不作为对外的产品成绩。
- 5 人样本只能暴露常见问题，不能证明“没有问题”。

记录与汇总使用同目录的 [USER_TEST_RECORD.xlsx](USER_TEST_RECORD.xlsx)。

## 指标与测法

| 路线图指标    | 本脚本中的任务 | 评分                               |
| ------------- | -------------- | ---------------------------------- |
| 30 秒定位测试 | T1             | 三个部分各 0/1，共 0–3             |
| 决策完成率    | T2             | 完成 / 部分 / 未完成               |
| 证据可达性    | T3             | 到达来源用的操作数，≤2 次记为可达  |
| 找证据耗时    | T3             | 秒；超过 180 秒记为未找到          |
| 事实辨识      | T4             | 每项 0/1；冲突项未出现时记“不适用” |
| 跨端任务完成  | T5             | 完成 / 部分 / 未完成               |

另在 T2、T3、T5 后各问一次单题易用性（SEQ，1–7 分）。

### 与路线图表述的差异

路线图写的是“区分事实、推断、未知和冲突”。公开快照不保证同时出现四类状态，知识库页面不一定能直接测这四类区分。主持人须在正式测试前使用当前版本试跑，不沿用历史记录数量或为了凑齐状态制造资料。

T4 改为在参与者自己的决策结果页上测：结果页把建议（判断）、建议依据（有来源的事实）、“影响决定的风险与未知”分区呈现，只有真实存在冲突时才出现“证据冲突”。冲突未出现时记为“不适用”，不另造冲突材料。

## 参与者

按路线图第 2 节的三类用户招募，共 5 人：

| 类型                | 人数 | 要求                                 |
| ------------------- | ---- | ------------------------------------ |
| 工程与架构负责人    | 2    | 近半年为项目选过模型、API 或编码工具 |
| 产品经理与创业团队  | 2    | 近半年参与过 AI 能力或供应商的选型   |
| AI 研究与行业观察者 | 1    | 定期跟进模型发布与版本变化           |

排除：参与过本项目开发、看过本项目演示或读过本项目文档的人。

## 测前准备

### 账号与费用

- 生成分析需要登录（页面提示“分析和保存个人任务需要登录，输入会保留”）。线上没有免登录查看决策结果的入口，原公开分享链接已返回 404。
- 测试前为每位参与者注册一个测试账号（P1–P5），不要使用参与者的真实邮箱。注册对公众开放，新账号为只读 `viewer` 角色。
- 注册过程不计入任何指标。每场从“未登录”开始，参与者遇到登录提示时，主持人提供该场账号。
- 需求解读的付费模型默认关闭（`decision_interpretation_enabled = False`），普通测试账号不会产生模型费用。
- 禁止参与者填写 API Key 或启用“自动 API 试用”。这会使用参与者或你的付费额度，也不属于本次测试范围。

### 试跑（每轮测试前必须做）

本脚本编写时没有登录账号，未能直接查看登录后的结果页。正式测试前，请用你自己的账号把下面三张任务卡各跑一遍，并在记录表“任务卡”页填写：

1. 实际出现的结果类型：给出建议，或没有合格候选；
2. 主选、备选或没有合格候选时显示的原因；
3. “建议依据”中一条可点开的来源，以及从结果到原文需要的操作数；
4. “影响决定的风险与未知”中的一项；
5. 是否出现“证据冲突”。

如果某张卡的实际结果和预期类型不符，先换卡或修改约束，再开始正式测试。评分时以试跑记录为对照。

### 设备与环境

- 桌面：无痕窗口，宽度不小于 1280px，起始页为空白页。
- 手机：参与者本人或准备好的真实手机，屏幕宽度约 390px，使用系统浏览器。
- 录屏和录音需征得同意；记录表、计时器各一份。
- 每场开始前访问 `https://ai-radar.xue-ai.workers.dev/backend/ready`，把返回的 `buildCommit` 前 7 位填入记录表。版本不同的结果不直接合并比较。

## 任务卡

给参与者纸质或另一屏幕上的卡片，不要口头改写。按参与者背景选一张，五场中三张卡都至少用一次。

**卡 A：文档问答（适合产品、研究）**

> 你的团队想让 AI 回答公司内部 PDF 和 Word 文档里的问题，回答要标明出处，找不到依据时要明确说不知道。先做小规模试点，数据可以使用云服务，预算有限。请用这个网站找出应该先试哪个方案，以及下一步怎么做。

**卡 B：编码工具（适合工程）**

> 你要为一个现有代码仓库选编码工具，需要能编辑文件、运行测试，效果优先。不接受只能在网页里聊天、不能操作仓库的工具。请用这个网站找出应该先试哪个，以及下一步怎么做。

**卡 C：私有部署（适合工程、产品；预期可能没有合格候选）**

> 你要为内部知识库选一个可以私有部署的模型，业务数据必须留在自己的服务器上，不能调用外部 API。请用这个网站找出能不能选、选哪个，以及下一步怎么做。

卡 C 用于观察“没有合格候选”时参与者能否看懂阻断原因和恢复路径。试跑结果如果给出了建议，照常使用，在记录表中注明。

## 流程（约 40 分钟）

| 时间     | 环节                |
| -------- | ------------------- |
| 0–3 分   | 开场                |
| 3–6 分   | 背景问题            |
| 6–9 分   | T1 30 秒定位        |
| 9–22 分  | T2 决策任务（桌面） |
| 22–28 分 | T3 找证据           |
| 28–31 分 | T4 事实辨识         |
| 31–36 分 | T5 手机复查         |
| 36–40 分 | 收尾访谈            |

### 开场（照读）

> 感谢参加。今天测试的是这个网站，不是你，不存在答错。请边操作边说出你在想什么，看到什么、想找什么、哪里不确定都可以说。我大多数时候不会回答问题，因为想看到你第一次使用时的真实情况。整个过程会录屏录音，只用于改进产品，可以吗？

### 背景问题

1. 你最近一次为工作选择 AI 模型、API 或工具，是在什么时候？选的是什么？
2. 当时是怎么做决定的？看了哪些资料？
3. 那次选择中，最难确认的是什么？

只记录，不追问到产品功能上。

### T1 30 秒定位测试

打开首页 `https://ai-radar.xue-ai.workers.dev/`，等内容加载完成后开始计时。

> 请随意浏览这个页面 30 秒，可以滚动，但先不要点击。

30 秒后请参与者把视线移开屏幕，或切到空白页：

> 用你自己的话说说，这个网站是做什么的？它大概有哪几块，每块能帮你做什么？

评分（每项 0/1，只要表达出意思即可，不要求用词一致）：

| 部分                         | 记 1 分的标准                              |
| ---------------------------- | ------------------------------------------ |
| 追踪器（动态）               | 说出能看到 AI 模型或产品最近的变化、更新   |
| 决策助手                     | 说出能按自己的任务或条件，帮忙给出选择建议 |
| 证据基础设施（知识库与来源） | 说出能查模型的版本、事实或背后的来源依据   |

参与者没提到某部分时，不要提示，直接记 0。

### T2 决策任务（桌面）

从首页开始，把任务卡交给参与者：

> 请按卡片上的情况，用这个网站完成任务。你觉得完成了就告诉我。

- 开始计时；参与者说“完成了”或放弃时停止。
- 遇到登录提示时，只说“这是这一场的账号”，提供 P 号账号，不解释其他内容。登录用时从总时间中扣除，并记录下来。
- 参与者卡住超过 2 分钟，只能使用中性提示：“你现在在找什么？”如果仍需要具体帮助，帮助后本任务最高记为“部分”。

完成后，在参与者仍能看到结果页时问：

1. 网站建议你先试哪个？还有没有备选？（没有合格候选时：为什么没有？接下来可以怎么做？）
2. 它为什么这样建议？
3. 你接下来具体会做什么？

评分：

| 结果   | 标准                                                                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 完成   | 提交了任务描述和卡片上的限制条件（至少两项，如预算、部署、不接受的条件）；能正确说出主选和备选，或说出没有合格候选的原因；能说出一个具体的下一步 |
| 部分   | 提交了，但复述错误；或漏掉限制条件；或需要具体帮助                                                                                               |
| 未完成 | 没有提交，或放弃                                                                                                                                 |

“正确”以试跑记录为准。另记录参与者是否误以为“可以试用”等于“效果已经验证”。

SEQ：

> 整体来说，完成这个任务有多容易？1 表示非常难，7 表示非常容易。

### T3 找证据（证据可达性与耗时）

参与者停留在 T2 的结果页上：

> 网站给出了这个建议。假设你要向同事证明它说的是对的，请找到支撑这条建议的原始资料，找到后指给我看。

- 读完指令立即开始计时；参与者指出原始来源（官方页面，或带来源链接的原文摘录）时停止。
- 只计点击或轻触，滚动不计。从结果页起算，每打开一层记 1 次操作。
- 180 秒仍未找到，记为“未找到”，并请参与者说说原本以为会在哪里。
- 参与者只指向网站的整理摘要而不是来源时，提示一次：“这是原始资料吗？”然后继续计时。

记录：操作数、用时（秒）、最终指向的位置。

SEQ 同 T2。

### T4 事实辨识

在 T2 的结果页上，主持人依次指出以下内容，每项问同一个问题：

> 这一条你会直接当作确定的事实来用吗？为什么？

| 项目         | 位置                                           | 记 1 分的回答                              |
| ------------ | ---------------------------------------------- | ------------------------------------------ |
| 有来源的事实 | “建议依据”或“当前证据”中的一条                 | 认为可以作为事实，并提到它有来源           |
| 系统的建议   | 结论或“建议与下一步”                           | 认为这是网站的判断或推荐，不是已证实的事实 |
| 未知项       | “影响决定的风险与未知”或“本次未核验项”中的一条 | 认为它目前不确定或未核验                   |
| 冲突项       | “证据冲突”或“事实冲突”，仅当出现时             | 认为资料之间有矛盾，需要再核对             |

追加一题：

> 页面上写着“可以试用，效果待测”。这是不是说明它在你的任务上效果好？

回答“不是，还需要自己试”记 1 分。

冲突项没有出现时记“不适用”，不要临时寻找其他页面替代。

### T5 手机复查（跨端）

请参与者在手机上用同一个 P 号账号登录，登录用时不计。

> 请在手机上找到刚才那份结果，说出建议先试哪个，并找到它的一条依据。

- 完成：找到结果、正确说出主选（或没有合格候选的原因），并打开一条依据。
- 部分：找到结果，但没能找到依据，或需要具体帮助。
- 未完成：没有找到结果，或放弃。
- 同时记录是否出现文字被截断、按钮够不着、需要横向滚动、底部导航遮挡内容等情况。记录表“T5 布局问题”只在确有问题时填写；没有问题请留空，汇总按“非空”计数。

如果测试账号没有保存这份研究，请参与者在手机上重新提交同一张任务卡，并在记录表中注明“手机重新提交”。

SEQ 同 T2。

### 收尾访谈

1. 今天哪一个地方最让你困惑？
2. 有没有哪里让你觉得“这个可以相信”或者“这个不太可信”？是什么让你这样觉得？
3. 下次真的要选模型或工具时，你会不会用它？在什么情况下会用？

不要问“你喜欢吗”，也不要解释设计意图。

## 主持人注意事项

- 不解释产品，不纠正参与者，不说“对/很好”。可以说“嗯”“请继续”。
- 参与者问“这个是什么意思”时，反问“你觉得是什么意思？”
- 当场记录原话，尤其是犹豫、误解和自我纠正。
- 每场结束后 10 分钟内补完记录表，再开始下一场。

## 测后整理

1. 在记录表“问题清单”页合并重复问题，标注严重程度和出现人数：
   - 阻断：无法完成任务；
   - 严重：完成了，但理解错误或明显绕路；
   - 轻微：犹豫、措辞困惑，不影响结果。
2. 每个问题附至少一句参与者原话，以及发生在哪个任务、哪个页面。
3. 只针对出现 2 人及以上，或任何“阻断”级问题提出修改；修改后用新的参与者复测同一任务，不重复使用本轮参与者。
4. 对外引用结果时写明样本量、日期、线上版本和任务卡，不写成百分比结论。
